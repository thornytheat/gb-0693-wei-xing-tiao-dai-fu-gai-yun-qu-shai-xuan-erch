# 数据定义

目标经度区间支持跨180度拆分；覆盖只算并集，云掩膜从有效条带扣除，重复条带不增加面积。

输入字段：scene, alias, west, east, cloud_w, cloud_e, quality, price, captured, version。所有ID按字符串保留；空字符串、NULL、N/A、未知与“-”视为缺失，不能当作数值零。数值使用Decimal，输出为十进制字符串。重复业务键相同内容计重复，内容冲突隔离或按明确修订号裁决，不按文件顺序盲目覆盖。

价格字段允许裸数字（默认CNY）或“数字+币种后缀”，如`100`、`100 USD`、`100USD`；当前支持CNY与USD，其他币种以CURRENCY原因码隔离。captured为ISO 8601时间，按UTC日历日提取报价日期；无法解析以DATE原因码隔离。

## 汇率快照与采购单

汇率来自离线JSON快照（默认`sample_data/fx_rates.json`，可用环境变量`FX_SOURCE`指向外部文件），结构为币种→报价日期→对CNY汇率。采购候选严格按每条报价的报价日期取当日快照汇率折算，快照缺当日记录以FX_MISSING隔离该报价，绝不推断或取最新值。汇率源载入失败时：若同原文存在历史批次则整体沿用旧版第6阶段候选（fx_status=fallback，记FX_FALLBACK），否则以空快照运行并隔离所有外币报价（fx_status=unavailable）。

复核通过才将采购单确认为“已确认”，台账(purchase_orders)锁定下单时的原币金额、币种、报价日期与下单汇率及折算CNY金额。之后任何重算都不得改写已确认成本；同场景的迟到报价（无论新旧、贵贱）以STALE_QUOTE隔离，不能倒退已确认单。重估差额_CNY列按最新快照对已确认外币单做只读重算（最新折算额−锁定折算额），仅供页面与导出核对，不回写成本；CNY单与候选单差额恒为0，快照不可用时差额也按0处理。

同原文摘要加规则版本构成run_id幂等键：重试同一报价批次复用批次、不新增采购单（台账主键run_id+canonical去重），历史批次数量不变。证据CSV的采购候选阶段同时给出原币金额、币种、下单汇率、折算金额_CNY、重估差额_CNY与采购状态，可逐行核对。

每条证据有原始行号，隔离记录有原因码及原值。时间区间使用半开边界；日期定义在各模块规则内显式声明。输入表头可调序，不得缺列或重复；中文旧编码可上传。规则版本存入运行清单，重跑使用原始文件内容摘要与规则版本共同确定幂等键。复核使用revision乐观锁，陈旧提交返回409。

固定纬带目标为[170,180)与[-180,-170)，只衡量经度覆盖宽度，不宣称球面面积。经度相同端点拒绝，避免无法区分全世界与空条带。采购使用预算1000 CNY的确定性边际覆盖/折算价格贪心，并非全局最优证明；同分按场景编号排序。贪心排名与预算约束均使用按报价日期汇率折算后的CNY金额，原币金额与下单汇率随采购单留痕。完整交付仍以区间并集核验。
